🔴 ROOT CAUSE: dipendenti.badge_uid NOT SET
─────────────────────────────────────────────────────────────────────────

PROBLEM:  Tag reads fail, no presence records created
CAUSE:    Employee badge_uid ≠ tag UID
SYMPTOM:  "TAG_NOT_REGISTERED" error
FIX:      UPDATE dipendenti SET badge_uid = '3605CA06' WHERE id = 'emp-id';
TIME:     2 minutes


🧬 CODE EXECUTION FLOW
─────────────────────────────────────────────────────────────────────────

1. Arduino reads tag UID (e.g., "3605CA06")
2. Arduino sends POST to /api/hardware/tag
3. Backend validates request
4. Backend queries dipendenti by badge_uid + company_id
   → If NULL → TAG_NOT_REGISTERED error (FAIL)
   → If found → Continue
5. Backend loads company's fasce_orarie (optional)
6. Backend gets last presence for this tag
7. Backend determines tipo (ENTRATA or USCITA)
   → With time ranges: Use range.tipo, invert if needed
   → Without time ranges: Toggle from last presence
8. Backend inserts into presenza table
9. Backend returns success response


🎯 TYPE DETERMINATION LOGIC
─────────────────────────────────────────────────────────────────────────

WITH TIME RANGES:
  Default = fascia.tipo (e.g., "Turno Mattino" = ENTRATA)
  If (last_presence.tipo == fascia.tipo AND last_presence in same range):
    tipo = opposite (ENTRATA → USCITA)

WITHOUT TIME RANGES:
  If (lastPresence.tipo == ENTRATA):
    tipo = USCITA
  Else:
    tipo = ENTRATA

FIRST EVER READ:
  Default = ENTRATA
